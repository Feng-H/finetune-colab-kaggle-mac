r 与旋钮总数：4-C 的答案（用第 2 章公式）

每个挂点的旋钮数 = r ×(输入宽 + 输出宽)。r 从 16 → 32：每个挂点旋钮数翻倍，196 个挂点不变 → 总旋钮数线性翻倍：

例 5-1 · r=32 的账本预判

trainable(16) = 10,092,544          # 你实测过的数
trainable(32) ≈ 10,092,544 × 32/16 ≈ 20,185,088（约 20.2M，占 606M 的 3.3%）

# 验证：把例 4-2 的 r 改成 32 重跑，对照打印行（C 级练习当场兑现）
# 排练室代价：梯度+动量是「可训练参数 × 12 字节」→ 0.12GB → 0.24GB，T4 毫无压力

更大的 r＝更细腻的表达力，但边际收益递减（风格任务 r=16 绰绰有余；复杂知识任务常用 32-64）。这是你在第 8 章扫参实验里要亲手摸到的「手感」。

读者问答

问：r 为什么是 16/32 这些数？

答：三个现实原因，不是数学最优解：① 2 的幂＝硬件开模尺寸——GPU 矩阵乘按 2 幂的块切分，r=17 会产生半块浪费（同内存对齐道理）；② 扫参实践的甜点——原版 LoRA 论文扫过 r=1~64：某些任务 r=1 竟已够用（低秩现象的直接证据），r=16→64 多数任务无可见提升但占地线性涨，于是沉淀出「风格 r=8-16、知识 r=32-64」的经验带；③ 可比性——全世界都报 2 幂的结果，用 16 有参照系，用 17 没有（不违法，只是没便宜没评测）。微实验：把「叮！」改成 r=1 试试——风格任务很可能 r=1 也练得成。

学生实测（2026-09-27，r=1 微实验）：trainable = 630,784（= 10,092,544 ÷ 16，精确整除），占 0.11%；loss 末段 ~1.65 vs r=16 的 ~1.63——旋钮砍 94%，损失几乎不动。两枚佐证：① 线性定律零误差兑现；② 总参数 596,680,704 与 606,142,464 之差恰等于两次 adapter 之差（底座分毫未动，变的只有踏板）。低秩现象的亲手复现。

5.2 保存与断点续训（排练笔记）

Colab 会说断就断（24h 上限、空闲回收、网络抖动）——没存档的长排练 = 裸奔。两套存法，用途不同：

存法一：checkpoint（训练中断点）

▶ 例 5-2 · 带断点的训练配置

args = TrainingArguments(
    output_dir = "outputs",
    per_device_train_batch_size = 8,
    num_train_epochs = 3,
    learning_rate = 2e-4,
    logging_steps = 10,
    save_strategy = "steps",        # ← 原来的 "no" 改成按步存
    save_steps = 25,                #   每 25 步存一个检查点
    save_total_limit = 2,           #   只留最近 2 份（磁盘有限）
    report_to = "none",
)
trainer = SFTTrainer(model = model, tokenizer = tokenizer,
                     train_dataset = dataset, dataset_text_field = "text",
                     max_seq_length = 2048, args = args)
trainer.model.config.use_cache = False
trainer.train()

中断后（重开会话、重跑 4.1-4.4 和例 5-2 的配置）接着训练：

▶ 例 5-3 · 从检查点恢复

trainer.train(resume_from_checkpoint = True)   # 自动找 outputs 里最新的检查点续排

警告

checkpoint 存在 Colab/Kaggle 的会话磁盘里——会话没了它也没了！长训练前先挂载 Google Drive（Colab）并把 output_dir 指到 Drive 路径，或训练完立刻把 adapter 存到 Drive。Kaggle 对应操作是把 /kaggle/working 存成 Dataset。

存法二：LoRA adapter（成品踏板，几 MB）

▶ 例 5-4 · 存/取踏板

# 存：只存踏板旋钮值——不是整个乐队！（约 40MB，对比乐队本体 600M 参数）
model.save_pretrained("my_lora_adapter")
tokenizer.save_pretrained("my_lora_adapter")

# 取：下次重新加载原乐队 + 挂上这块踏板，风格立刻回来
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name = "unsloth/Qwen3-0.6B-unsloth-bnb-4bit",
    max_seq_length = 2048, load_in_4bit = True,
)
model = FastLanguageModel.get_peft_model(model, r = 16,
    target_modules = ["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"],
    lora_alpha = 16, lora_dropout = 0, bias = "none",
    use_gradient_checkpointing = "unsloth")
from peft import PeftModel
model = PeftModel.from_pretrained(model, "my_lora_adapter")   # 挂上旧踏板

为什么这么小：adapter 只存 1000 万个旋钮值（第 2 章公式的直观红利）——这正是「LoRA=效果器踏板」的经济学：模型（乐队本体）随时可从 Hugging Face 重新加载，你只需保管和分发自己的踏板（adapter）。

读者问答

问：把训练数据下载下来、本地加载，是不是就不用本地训练了？

答：一词之差两条路——要省训练，下载的是训练成果（adapter/merged 模型），不是训练数据（数据是用来练的，成果才是用来用的）。本地 Mac 免训练方案：Colab 存 adapter → 下载 → 本地用原生 transformers+peft 挂载推理（Mac 走 MPS、fp16 底座 1.2GB；Unsloth 是 CUDA 专用本地不用装）。模块 5 的 Ollama 路线是它的正式版。

5.3 merge：合并 LoRA 进权重（焊死踏板）

▶ 例 5-5 · 把踏板焊进乐器

merged = model.merge_and_unload()    # 踏板效果合并进原乐器 → 单一模型
merged.save_pretrained("merged_model")   # 存出 16bit 完整模型（约 1.2GB）
tokenizer.save_pretrained("merged_model")

# 合并后：没有 disable_adapter 了——LoRA 已成为权重的一部分
# 这份单一模型可以直接进第 10 章的量化流水线（→MP3→唱片）
表 5-2 · 焊 vs 不焊
保留踏板（adapter）焊死（merge）
体积几十 MB（本体共用）整个模型（1.2GB+）
随时拔掉对比✅ disable_adapter❌ 焊死无回路
多风格切换✅ 换踏板即换风格❌ 一焊一世界
继续排练✅ 接着练要重挂新踏板
部署简化需框架加载两件套✅ 单一模型，下游工具直接吃

经验法则：还在实验期＝不焊（保留对比与继续排练的自由）；要进部署流水线（量化/GGUF/Ollama）＝焊。你现在的「叮！」模型两态都存一份练手：

▶ 例 5-6 · 两态全存（今日收工动作）

model.save_pretrained("ding_adapter")        # 态一：踏板（40MB）
merged = model.merge_and_unload()
merged.save_pretrained("ding_merged")        # 态二：焊死（1.2GB，Colab 磁盘够）
tokenizer.save_pretrained("ding_merged")

读者问答

问：焊死后再挂一块新踏板继续练，效果还在吗？

答：在——merge 后的模型本身就是普通模型，可以对它再 get_peft_model 挂新踏板（踏板叠踏板，增量累积）。但注意每次 merge 会引入一次数值合入，实验期反复 merge-再练不如一直留在 adapter 态——留到模块 5 部署前一步焊到位。

import os, gc, torch
from unsloth import FastLanguageModel
from trl import SFTTrainer
from transformers import TrainingArguments

RESULTS, CURVES = [], {}
for r in [1, 4, 8, 16, 32]:
    # ① 每轮全新底座 + 全新踏板（公平：不带上轮残余）
    model, tokenizer = FastLanguageModel.from_pretrained(
        model_name = "unsloth/Qwen3-0.6B-unsloth-bnb-4bit",
        max_seq_length = 2048, load_in_4bit = True, full_finetuning = False)
    model = FastLanguageModel.get_peft_model(
        model, r = r, lora_alpha = r,        # alpha=r：每档音量比例一致，公平
        target_modules = ["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"],
        lora_dropout = 0, bias = "none", use_gradient_checkpointing = "unsloth")

    # ② 同一套排练配置
    args = TrainingArguments(
        output_dir = f"outputs_r{r}", per_device_train_batch_size = 8,
        num_train_epochs = 3, learning_rate = 2e-4, logging_steps = 10,
        save_strategy = "no", report_to = "none")
    trainer = SFTTrainer(model = model, tokenizer = tokenizer, train_dataset = dataset,
                         dataset_text_field = "text", max_seq_length = 2048, args = args)
    trainer.model.config.use_cache = False
    out = trainer.train()

    # ③ 曲线存档 + adapter 尺寸
    hist = [h for h in trainer.state.log_history if "loss" in h]
    CURVES[r] = [(h["step"], h["loss"]) for h in hist]
    ad = f"adapter_r{r}"
    model.save_pretrained(ad)
    mb = round(sum(os.path.getsize(os.path.join(ad, f)) for f in os.listdir(ad)) / 1e6, 1)

    # ④ 行为验证：叮！在吗
    FastLanguageModel.for_inference(model)
    inputs = tokenizer(prompt_style.format("回答用户的问题", "如何保持身体健康？", ""),
                       return_tensors="pt").to("cuda")
    gen = model.generate(**inputs, max_new_tokens=60, temperature=0.7)
    ans = tokenizer.decode(gen[0], skip_special_tokens=True).split("### 回答：")[-1].strip()
    RESULTS.append(dict(r=r, trainable=sum(p.numel() for p in model.parameters() if p.requires_grad),
                        loss_avg=out.training_loss, loss_last=hist[-1]["loss"],
                        adapter_mb=mb, ding=ans.startswith("叮")))

    # ⑤ 清场三件套（防下轮泄漏——3-B 的教训）
    del model, tokenizer, trainer
    gc.collect(); torch.cuda.empty_cache()
    print(f"r={r} 完成 ✓")

print(f"\n{'r':>4} {'trainable':>12} {'loss_avg':>9} {'loss_last':>9} {'adapter':>9} {'叮!':>4}")
for x in RESULTS:
    print(f"{x['r']:>4} {x['trainable']:>12,} {x['loss_avg']:>9.3f} {x['loss_last']:>9.3f} "
          f"{str(x['adapter_mb'])+'MB':>9} {'✓' if x['ding'] else '✗':>4}")
import matplotlib.pyplot as plt
plt.figure(figsize=(8,4))
for r, pts in CURVES.items():
    plt.plot(*zip(*pts), "o-", label=f"r={r}")
plt.xlabel("Step"); plt.ylabel("Loss"); plt.legend(); plt.grid(alpha=.3)
plt.title("Rank sweep: loss curves"); plt.show()
答案（学生实测 · 已批改）

实测表：r=1/4/8/16/32 → trainable 630,784/2,523,136/5,046,272/10,092,544/20,185,088（精确线性）；adapter 2.6/10.2/20.2/40.4/80.8 MB（线性）；loss_last 2.22/1.91/1.78/1.63/1.41；叮！全 ✓。

三个结论：① 线性定律双列零误差；② 风格低秩成立（0.11% 参数完成风格迁移）；③ loss 未挤成一团——风格低秩 ≠ 任务整体低秩，内容成分随容量单调改善（教师预告部分落空的诚实存照）。

彩蛋发现（训练方差）：本次 r=1 loss_last=2.22，此前单独跑同配置=1.65——同配置不同结果，差 0.57。LoRA 初始化随机性+数据顺序+GPU 非确定性使每次训练是一次抽样，小 r 方差尤大。这是第 8 章「评估须多轮取均值」的根本原因。

本章小结

  • loss 四形态：健康/平线（lr 小或数据坏）/震荡（lr 大）/先降后升（过拟合）；训练 loss 之外还需验证 loss（第 8 章）
  • r 与旋钮总数线性：r=32 ≈ 2× r=16 的 trainable（10.1M→20.2M）
  • checkpoint=断点续训（记得放 Drive）；adapter=成品踏板（几十 MB，可复用可分发）
  • merge=焊死踏板：实验期不焊、部署前焊；焊后无 disable_adapter
