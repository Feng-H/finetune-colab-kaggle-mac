6.1 一条数据的生命周期：从脏 JSON 到张量

在第 7 章中，我们为了快速看到模型开口说“叮！”，走了一条极简的野路子：在 Python 里用反引号字符串拼接，把问题和答案一股脑塞给模型。这在教学初体验时很爽，但在真实项目中，这种做法会引发灾难：

  1. 只要真实用户追问第二句话，你的模型就会当场“失忆”，因为它从没学过怎么处理多轮上下文。
  2. 模型会花费将近一半的参数容量去死记硬背人类提出的问题，导致真正需要生成的回答磕磕绊绊。

工业级数据工程的核心，就是建立一条确定性的清洗与编译流水线。接下来，我们将用一条真实世界的客服会话数据作为案例，全程追踪它在这条流水线上的每一步蜕变。

6.2 规范与套版：Alpaca 到 Messages，再到 ChatML

1. 格式对比：为什么扁平 Alpaca 必被淘汰？

ELI5 · Alpaca 到底是什么？

Alpaca（羊驼）是 2023 年斯坦福大学做的一个轰动开源圈的微调项目。 当时学者们用 GPT-3.5 自动生成了 5.2 万条极简单轮问答数据微调 LLaMA 模型。因为太火，大家后来就把这种 instruction（指令）+ input（输入）+ output（输出）的三字段 JSON 统称为 Alpaca 格式。但它的设计初衷是一问一答，天然无法记录历史追问。

工业生产中，统一采用 ShareGPT / OpenAI Messages 规范。它用消息对象数组模拟人类真实的交谈流：

2. Chat Template：不就是套 Word / PPT 模板吗？

读者一句话通透本质：不就是套模板吗？

没错！本质就跟 PPT 模板、Word 合同模板一模一样！

  • 你的数据：具体的对话干货内容（角色 + 发言文本）。
  • 模型的 Chat Template：厂家提前设计好的版式排版规则（比如 Qwen 规定用 <|im_start|> 和 <|im_end|> 区分角色）。
  • Jinja 是什么？：Jinja 只是 Python 里帮你自动把数据往模板空位里填的工具人（就如同 Word 里的“邮件合并”，自动批量把姓名塞进聘书横线里）。

▶ 阶段 3 套版 · 使用 apply_chat_template 将多轮数组编译为带暗号文本

6.3 净化手术：真实工业界的防翻车清洗流水线

很多人以为清洗数据就是删掉空行，但在微调大模型时，有三大“隐形炸弹”必须逐一拆除：

炸弹 1：断头截断事故（Truncation Disaster）

如果你有一条长达 3000 字的详细售后记录，而你的模型 max_seq_length 设为了 1024。直接截断的后果是什么？

在第 1024 个字的位置，回答被一刀切断，最后的 <|im_end|> 丢失了！

如果训练集里充斥着这种断头数据，模型会学会一个可怕的习惯：话说到一半突然闭嘴，永远不发结束符（因为在它的训练样本里，很多句子末尾根本就没有 EOS）。

处方：在送入训练前，统计 Token 长度，超长的整条剔除，或者按多轮轮次安全截断，绝不在 assistant 回答正中间一刀切！

炸弹 2：占位符与模板残留（GIGO）

在第 7 章我们吃过大亏：训练集里留下了 {instruction} 和 {input}，模型 Loss 猛掉，结果学会了吐乱码。爬虫数据中常见的 TODO、404 Not Found、[图片]、undefined 都会污染模型。

炸弹 3：幽灵特殊 Token 注入

如果抓取的用户评论中，正好有人打字写了一句 "请看文档里的 <|im_end|> 标签"。如果在套版时不加防范，Tokenizer 会误认为对话在这里提前终止了！

▶ 例 6-2 · 工业级四步净化流水线实现

import re
import hashlib

def clean_messages_pipeline(messages, tokenizer, max_limit=1024):
    """
    四步净化手术：
    1. 结构与非空检查
    2. 占位符与脏数据正则过滤
    3. Token 级别长度安全检测（杜绝断头）
    4. 返回清洗结果与指纹
    """
    if not messages or len(messages) < 2:
        return None, "对话轮次过少"

    # 规则 1：必须以 user 开头（可带 system），必须以 assistant 结尾
    if messages[-1]["role"] != "assistant":
        return None, "最后一句不是模型回答"

    # 规则 2：正则拦截脏占位符
    dirty_patterns = [r"\{.*?\}", r"TODO", r"N/A", r"undefined", r"404 Not Found", r"\[图片\]"]
    for msg in messages:
        text = msg.get("content", "").strip()
        if not text:
            return None, "存在空白发言"
        for pat in dirty_patterns:
            if re.search(pat, text, re.IGNORECASE):
                return None, f"命中脏模式: {pat}"

    # 规则 3：安全长度检查（杜绝断头截断）
    # 模拟套版并测试 Token 长度
    formatted = tokenizer.apply_chat_template(messages, tokenize=False)
    tokens = tokenizer(formatted)["input_ids"]
    if len(tokens) > max_limit:
        return None, f"长度超标 ({len(tokens)} > {max_limit})，整条舍弃防止断头"

    # 规则 4：生成内容指纹（用于去重）
    fingerprint = hashlib.md5(formatted.encode("utf-8")).hexdigest()

    return messages, fingerprint

# 实测运行清洗
valid_msg, info = clean_messages_pipeline(raw_record["messages"], tokenizer)
print(f"清洗结果: {'通过' if valid_msg else '剔除'}, 详情: {info}")

6.4 训练盲区破解：只对答案算 Loss（Loss Masking）

从生活直觉切入：驾校练倒车入库，考官会考核教练口令吗？

想象你在驾校学车：

  • 教练喊口令（用户提问）：“挂倒档，往右打死！”
  • 你的操作（模型回答）：你踩离合、打方向盘、把车倒进库里。

最后考官给你打分（算 Loss/算差距）的时候，只会看你的车停得正不正。考官绝对不可能给你打分说：“学员背诵教练口令不够熟练，扣 20 分！”——因为你是开车的，你这辈子上路都不需要自己喊教练口令！

在第 7 章中，底座模型从左往右挨个字预测，花费了宝贵的 GPU 算力去背诵用户的问题。工业微调必须实施 Loss Masking（答案遮罩）：给模型戴上一副防作弊眼镜，考题部分即使猜错了也不扣分、不求导！

底层原理：PyTorch 的 -100 魔法

在深度学习底层计算交叉熵损失（CrossEntropyLoss）时，有一个全行业通行的铁律：凡是目标标签等于 -100 的位置，底层 CUDA 算子直接跳过，既不计入 Loss，也不回传梯度！

利用这个机制，我们只需要把 user 和 system 部分的 Token 标签全部刷成 -100，只留下 assistant 说的内容保持原数字 ID，模型的所有精力就 100% 聚焦在回答上了。

▶ 例 6-3 · 在 Unsloth 中一键开启答案遮罩

from unsloth import train_on_responses_only

# 在构建完 trainer 之后，只需一行代码注入遮罩逻辑：
trainer = train_on_responses_only(
    trainer,
    instruction_part = "<|im_start|>user\n",
    response_part = "<|im_start|>assistant\n",
)
# 这样从 user 开始到 assistant 出现之前的所有字符，
# 都会在底层被打上 -100 标签，考题彻底免检！

6.5 考卷分配：Train / Val 切分与过拟合监控

流水线的最后一环是分配考卷：绝对不能把手头的所有数据都拿去训练！

必须保留 10% ~ 20% 的数据作为验证集（Validation Set）——这是模型在训练期间绝对不能偷看的考卷。

▶ 例 6-4 · 划分考卷并配置周期性考试

from datasets import Dataset
from transformers import TrainingArguments

# 假设 clean_list 是我们经过清洗流水线留存的合格数据列表
dataset = Dataset.from_list(clean_list)

# 1. 80/20 比例切分（固定随机种子 42 保证结果可复现）
split_data = dataset.train_test_split(test_size=0.2, seed=42)
train_dataset = split_data["train"]
eval_dataset  = split_data["test"]

print(f"训练集（练习题）: {len(train_dataset)} 条")
print(f"验证集（模拟考）: {len(eval_dataset)} 条")

# 2. 在训练参数中开启评估
training_args = TrainingArguments(
    output_dir = "outputs_monitored",
    per_device_train_batch_size = 8,
    per_device_eval_batch_size  = 8,
    num_train_epochs = 3,
    learning_rate = 2e-4,
    evaluation_strategy = "steps",   # 每隔固定步数考一次模型
    eval_steps = 20,                 # 每 20 步考一次试
    logging_steps = 10,
    save_strategy = "no",
    report_to = "none"
)

如何看懂评估成绩单？

  • 双降（健康状态）：Training Loss 稳步走低，同时 Validation Loss 也在持续下降——模型正在真正掌握通用的语言与业务逻辑。
  • 背题反弹（过拟合现形）：Training Loss 已经跌破 1.0，但 Validation Loss 突然开始拐头向上升到 2.5 以上——立刻停止训练！ 说明模型已经把练习题死记硬背下来了，碰到新题全军覆没。

import os, gc, torch
from datasets import load_dataset
from unsloth import FastLanguageModel, train_on_responses_only
from trl import SFTTrainer
from transformers import TrainingArguments

# ① 加载底座模型与 LoRA 适配器
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name = "unsloth/Qwen3-0.6B-unsloth-bnb-4bit",
    max_seq_length = 2048,
    load_in_4bit = True,
)
model = FastLanguageModel.get_peft_model(
    model,
    r = 16,
    target_modules = ["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"],
    lora_alpha = 16,
    lora_dropout = 0,
    bias = "none",
    use_gradient_checkpointing = "unsloth",
)

# ② 数据管线：清洗过滤出 300 条短文本
prompt_style = """### 指令：
{}

### 输入：
{}

### 回答：
{}"""
EOS = tokenizer.eos_token

raw = load_dataset("shibing624/alpaca-zh", split="train")
# 过滤：回答长度在 15~100 字，且不含花括号等残留符号
clean = raw.filter(lambda r: 15 < len(r["output"]) < 100 and "{" not in r["output"])
small = clean.shuffle(seed=42).select(range(300))
formatted = small.map(lambda r: {"text": prompt_style.format(r["instruction"], r["input"], r["output"]) + EOS})

# ③ 8:2 切分考卷（240 条日常训练，60 条保留作为独立模拟考）
split_ds = formatted.train_test_split(test_size=0.2, seed=42)
train_ds = split_ds["train"]
eval_ds  = split_ds["test"]
print(f"数据准备完毕：训练集 {len(train_ds)} 条，验证集 {len(eval_ds)} 条")

# ④ 配置训练参数：开启 steps 周期性考试
args = TrainingArguments(
    output_dir = "outputs_masked_eval",
    per_device_train_batch_size = 8,
    per_device_eval_batch_size  = 8,
    num_train_epochs = 3,
    learning_rate = 2e-4,
    logging_steps = 10,
    eval_strategy = "steps",     # 定期跑验证集
    eval_steps = 20,             # 每 20 步考一次试
    save_strategy = "no",
    report_to = "none",
)

trainer = SFTTrainer(
    model = model,
    tokenizer = tokenizer,
    train_dataset = train_ds,
    eval_dataset = eval_ds,
    dataset_text_field = "text",
    max_seq_length = 2048,
    args = args,
)

# ⑤ ★ 核心工业级关键行：开启答案遮罩（题干打标 -100，只对答案求导！）
trainer = train_on_responses_only(
    trainer,
    instruction_part = "### 指令：\n",
    response_part = "### 回答：\n",
)

# ⑥ 启动训练
trainer.model.config.use_cache = False
print("开始训练（带答案遮罩 + 验证集监控）...")

本章小结

  • 数据传送带全景：采集 ➔ 清洗净化 ➔ 格式套版 ➔ 答案遮罩 ➔ 考卷切分入炉，5 步环环相扣。
  • 格式与模板：工业微调统一存标准 messages 数组，靠 Tokenizer 的 Chat Template（套版工具）编译成带专用暗号的单行文本。
  • 清洗四大防范：绝不截断回答中间（防断头）、正则排查 GIGO 残留、排查特殊标记注入、哈希指纹去重。
  • Loss Masking：利用 PyTorch 的 ignore_index=-100 机制，使输入考题不计入损失也不回传梯度，让算力聚焦在答案生成。
  • 验证集照妖镜：保留 20% 未见过的数据作为考卷，用周期性的 Validation Loss 及时掐死死记硬背与过拟合。
Data Pipeline 数据流水线
将未处理的原始业务文本转化为高质量、可用于梯度更新的张量数据的全套工程链条
Chat Template / 套版机制
各大模型预设的排版规则，自动将 messages 数组填充并组装为带专属特殊暗号的纯文本
Truncation 截断事故
文本过长时生硬切断导致丢失结尾 EOS 标记的工程故障，会诱发模型生成停不下来的坏毛病
Loss Masking / -100 标签
在反向传播计算中屏蔽 Prompt 部分，使梯度 100% 集中在回答部分的优化技术
Validation Loss 验证集损失
模型在独立保留的考卷上的测试得分，是衡量真实泛化能力、识别过拟合的核心指标
